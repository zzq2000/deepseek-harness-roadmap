# 先跑起来，再看地图

这一章不讲任何机制，只做三件事：说清 DSH 是什么、列出把它跑起来所需的环境、教你在 20 万行代码里找到任何一段实现。

---

## 一个论断

DeepSeek Harness（下称 **DSH**）是一个 agent harness：把大模型接上工具、文件系统、终端、沙箱，让它能真的干活的那层运行时。这类东西你见过不少，Claude Code、Codex、Cline 都是。

但 DSH 有一个把它和大多数同类分开的设计决定，写在 {{src:AGENTS.md|AGENTS.md}} 的第一行：

> **everything is a plugin**

这句话在很多项目里是市场辞令，在 DSH 里是字面意义。{{src:docs/architecture.zh.md#L11-L13|architecture.zh.md}} 把话说得更死：

> 不存在需要打补丁的特权内核：扩展 dsh 的方式是把插件挂载到其他插件旁边，而各项注册都是副作用，会在其插件卸载时撤销。

请认真对待"**没有特权内核**"这半句。它的意思是：模型适配器是插件，工具注册表是插件，会话日志是插件，**agent loop 本身也是插件**。没有一个 `main()` 函数在顶层调度这一切，也没有一个 `core` 模块是其他模块必须绕开的。一个运行中的 `dsh` 进程，是一棵按配置文件组装起来的插件树。

:::key 这门课的中心问题
如果连主循环都是可替换的插件，那么"控制流"到底在哪里？答案是：在**事件**和**服务解析**里。这是第 1、2 章要回答的问题，也是读懂后面一切的前提。
:::

这个设计对你的直接意义是：**自进化、记忆机制、多智能体排布，都不需要改 DSH 的代码**。它们是挂在已有扩展点上的新插件。这也是第 12 章的目标。

这套插件模型不是工程习惯，它有形式化的底子。DSH 的 {{src:README.zh.md#L7|README 第 7 行}} 指向一篇论文：

> _A Programming Paradigm for Spatiotemporal Composability_，Yifan Shi、Wei Zhang、Tianyi Cui，北京大学与 DeepSeek-AI。88 页，2026 年 8 月 13 日草稿。[仓库](https://github.com/cordiverse/paper) · [PDF](https://github.com/cordiverse/paper/blob/main/paper.pdf)

它把「动态组合」拆成时间与空间两个维度，正好是本课第 1、2 章的内容，而摘要里点名的应用场景就是 self-evolving agent harness。**现在不用读它**，第 2 章末尾会在你读完源码之后做一次完整的对照解读。

## 这堆代码有多大

先给你一个诚实的量级，免得你低估或高估：

| 口径 | 数量 |
|---|---|
| `packages/` 下的包组 | 49 |
| 叶子包（真正的 npm 包） | 219 |
| 产品 TypeScript 代码（不含测试） | 约 **20.7 万行** / 1292 个文件 |
| 含测试与前端全量 | 约 45 万行 |
| Cordis 框架内核（`vendor/cordis/src`） | **2693 行** |

注意最后一行。整个"一切皆插件"的地基（Context、插件生命周期、服务解析、事件总线）只有 **2693 行**。这 2693 行是这门课性价比最高的部分：读透它，剩下 20 万行都会变成"在这个框架上的应用"，而不是 20 万行陌生代码。

所以课程的顺序不是从 `main` 开始，而是从**框架内核**开始。第 1、2 章会把这 2693 行里最关键的部分逐行读完。

## 环境要求

动手实验从第 3 章开始，需要能构建并运行 DSH。先对照这张表检查环境：

| 组件 | 要求 | 检查命令 | 用途 |
|---|---|---|---|
| **Node.js** | `^22.19.0 \|\| >=24.0.0` | `node -v` | 运行时；版本不符 pnpm 会直接拒绝安装 |
| **pnpm** | 11.x | `pnpm -v` | 包管理；仓库是 pnpm workspace，用 npm/yarn 装不起来 |
| **Git** | 任意 | `git --version` | 拉取仓库 |
| **DeepSeek API Key** | 有效密钥 | 见下文 | 运行 agent；纯读源码不需要 |
| 磁盘 | 约 3 GB | `df -h .` | `node_modules` 与构建产物 |

版本要求的权威出处是仓库的 `package.json`，不是本文：

```srcref package.json#L7-L10
packageManager 与 engines 字段。版本要求以这里为准，本课的表格只是转述。
```

:::note 不装 pnpm 也能读前两章
第 1、2 章读的是 `vendor/cordis` 的源码，纯阅读，不需要安装任何东西。真正需要构建的是第 3 章起的动手实验。想省时间可以现在就把安装和构建挂在后台，读完两章正好构建完。
:::

### 安装与构建

```sh
corepack enable          # Node 自带 corepack，用它装 pnpm 最省事
cd deepseek-harness
pnpm install
pnpm run build           # 首次构建通常十几分钟
```

`corepack enable` 会按仓库 `package.json` 里 `packageManager` 声明的版本自动准备 pnpm，比全局 `npm i -g pnpm` 更不容易装错版本。

### 运行

```sh
pnpm dsh web             # 启动 Web UI，默认 http://127.0.0.1:3080
pnpm dsh --profile headless "统计这个仓库有多少个包"   # 一次性任务
```

两者都需要 `DEEPSEEK_API_KEY`。DSH 从仓库根目录的 `.env` 读取它，格式是：

```sh
DEEPSEEK_API_KEY=sk-...
```

密钥策略见 {{src:AGENTS.md#L94-L96|AGENTS.md 的 Secrets / .env 一节}}。没有密钥时，实时 API 测试会自行跳过，纯阅读和本课的选择题都不受影响，但本课的**开放题判卷需要它**。

:::warn 别把密钥提交进仓库
`AGENTS.md` 明确写了 "Never commit credentials"。`.env` 已在 `.gitignore` 中。
:::

还有一条你现在就该记住的命令，它是理解整个系统装配的钥匙：

```sh
pnpm dsh --profile web --dump-config
```

它把这台机器实际启动的**完整插件树**打印出来。里面的每一个条目，都可以被你自己的 patch 文件替换掉。第 3 章会逐行解释它的输出。

## 在 20 万行里找东西

这是本章最实用的部分。DSH 的文档质量异常高，找代码有三条正规路径，按优先级：

### 路径一：子系统参考页

{{src:docs/subsystems/README.zh.md|docs/subsystems/}} 下有 **46 个**子系统页，一个子系统一页，中英双语。想知道"压缩是怎么做的"，直接看 `compaction.zh.md`；想知道"沙箱怎么限制进程"，看 `sandbox.zh.md`。

这些页面有个别处罕见的性质：页面上的类型声明和源码由 CI 校验，不允许漂移。

```srcref docs/subsystems/README.zh.md#L55-L55
"这些页面上的类型声明及其 JSDoc 与源码等价，并由 `pnpm run verify-type-equiv` 检查漂移"
```

所以你可以放心把它们当权威，而不用担心文档过期。这也是我在写这门课时敢大量引用它们的原因。

### 路径二：包组 README

`packages/<组>/README.md` 负责**包与 `ctx` 键的映射**。比如你在代码里看到 `ctx.shell`，想知道它是谁提供的，就去 {{src:packages/shell|packages/shell/}} 的 README。

{{src:packages/README.zh.md|packages/README.zh.md}} 是这一层的总索引，49 个组一张表。

### 路径三：右侧的搜索框

顶栏搜索框直连仓库的全文搜索（`Cmd/Ctrl+F` 聚焦）。代码视图里**点击任何类型名或函数名**会弹出它的定义位置。这两个功能是我为这门课专门做的，因为读 DSH 最花时间的动作就是"这个类型到底在哪定义的"。

:::lab 现在就试一下
1. 在顶栏搜索 `agent/pre-step`，看看这个事件有多少个生产方和消费方。
2. 点开右侧文件树，展开 `vendor/cordis/src/`，打开 `fiber.ts`。
3. 在 `fiber.ts` 里点击任意一个 `Context` 或 `Disposable`，看符号跳转是否把你带到定义处。

做完这三步，你就掌握了这门课 80% 的操作方式。
:::

## 一次对话，在磁盘上是什么

最后建立一个具体的心理图像。当你和 DSH 对话时，磁盘上到底存了什么？

答案是**一条只追加的事件日志**。默认位置在 harness home（`~/.dsh`，见 {{src:packages/util/home-paths/src/index.ts#L12|DSH_HOME_DIR_NAME}}），布局是：

```text
<root>/
  --<规范化的项目路径>--/
    <会话 id>/
      session.jsonl.zstd      # 默认：带校验和的 zstd 帧拼接
      session.jsonl           # 仅当 compression: 'none'
```

日志的第一行是不可变的 `SessionHeader`，之后每一行是一条 `SessionEvent`。你的每句话、模型的每个流式分片、每次工具调用与结果，都是日志里的一条事件。

这条日志不是"聊天记录的副产品"，而是**模型上下文的唯一来源**。DSH 有一条运行时不变量强制这一点：

:::key 模型可见 ⟺ 已记录
任何抵达模型请求的内容，都必须能从会话日志重建。因此"增加一项模型可见的输入"这件事，必然要求"新增一个会话事件类型"。

这条规则是第 4 章的主题，但现在就记住它，它解释了后面很多看起来绕的设计。
:::

:::note 想直接看日志？
默认是 zstd 压缩的，`cat` 出来是乱码。JSONL 后端支持 `compression: 'none'` 配置项（见 {{src:packages/session/session-persistence-jsonl/README.zh.md|该包的 README}}），改成明文就能直接读。第 4 章的实验会用到这一招。
:::

## 这门课怎么读

- **左边讲解，右边源码。** 正文里所有带 ◆ 的行内引用和蓝色边框的卡片，点一下右侧就会打开对应文件并高亮到具体行。**请真的去点**。这门课的设计前提是你在对照源码读，而不是只读我的转述。
- **先选择题，再问答题。** 选择题查事实记忆，本地即时判；问答题查机制理解，会连同**该题的源码上下文**一起送去 DeepSeek 判卷，它会指出你漏了什么、说错了什么。
- **判卷刻意严格**，特别针对"术语用对了但机制说反了"这种情况。被扣分的地方就是该回去重读的地方。
